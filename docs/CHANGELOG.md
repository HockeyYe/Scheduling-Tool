# 更新与开发日志

## 2026-06-09

本次更新主要围绕前端显示问题和普通用户操作体验进行调整，不涉及后端、数据库、登录系统，也没有修改排班算法的核心计算逻辑。

### 1. 修复员工详情面板内容溢出

问题：

- 在“员工与可用时间”页面右侧员工详情面板中，姓名输入框会超出卡片容器。
- 下方的状态说明标签文字较长时也会撑出容器范围。
- 目标工时滑杆在窄面板中缺少明确的宽度约束。

处理：

- 为员工详情面板增加局部样式类，避免影响其他页面和班表标签。
- 让姓名输入框和目标工时滑杆按容器宽度收缩。
- 让员工详情面板内的长标签支持自动换行。

涉及文件：

- `src/app/App.tsx`
- `src/styles/globals.css`

### 2. 去掉排班表员工姓名后的感叹号

问题：

- 排班结果中部分员工姓名后会显示 `!`。
- 该符号原本表示短班风险，但在周视图班表里容易被误认为是员工姓名的一部分或显示错误。

处理：

- 移除周视图班表里直接显示的 `!`。
- 保留底层 `shortShiftRisk` 数据，不影响短班风险计算，也不影响后续如果需要单独展示短班提醒。

涉及文件：

- `src/app/App.tsx`

### 3. 简化算法参数权重设置

问题：

- “算法参数”中的四个软约束权重原本使用 0-100 的细粒度滑杆。
- 面向普通用户时，这种数值调节过细，理解和操作成本偏高。

处理：

- 保留“最短连续班次”的小时滑杆不变。
- 将以下四个权重改为三档选择：
  - 缺人惩罚
  - 公平性
  - 偏好冲突
  - 连续班次
- 三档内部仍映射为数字权重，兼容现有算法输入：
  - 低：30
  - 中：60
  - 高：90
- 已有历史数据如果仍是 0-100 的细粒度数值，界面会显示最接近的低、中、高档位。
- 默认示例数据同步调整为：
  - 缺人惩罚：高
  - 公平性：中
  - 偏好冲突：中
  - 连续班次：中

涉及文件：

- `src/app/App.tsx`
- `src/styles/globals.css`
- `src/features/project/defaultProject.ts`

### 4. 去掉三档权重控件右上角重复标签

问题：

- 三档权重控件上方右侧额外显示当前档位，例如“高”“中”。
- 当前档位已经通过按钮高亮体现，重复文字会增加视觉噪音。

处理：

- 移除三档权重控件标题行右侧的当前档位文字。
- 保留按钮高亮状态。
- “最短连续班次”右侧的小时数显示保持不变。

涉及文件：

- `src/app/App.tsx`

### 5. 增强可用时间录入的批量编辑能力

问题：

- 过去录入员工可用时间时，只能逐个点击时间格修改状态。
- 当员工有连续课程、整段忙碌时间或跨多天重复时间段时，逐格点击效率较低。
- 状态按钮始终有一个默认选中状态，容易让用户误以为点击或拖拽后会立即修改表格。

处理：

- 在“员工与可用时间”页面的单员工时间表中加入矩形选区能力。
- 支持通过鼠标拖拽选择多个时间格，拖拽结束后保留选区。
- 状态按钮不再默认必须选中一个；只有存在选区时才可点击。
- 点击 `可排`、`忙碌`、`不偏好` 后，将当前选区批量设置为对应状态。
- 状态按钮选中时使用与表格标签一致的颜色反馈：
  - `可排` 使用绿色。
  - `忙碌` 使用蓝色。
  - `不偏好` 使用黄色。
- 点击其他单元格、表格外区域或切换员工后，会清空当前选区。

涉及文件：

- `src/app/App.tsx`
- `src/styles/globals.css`

### 6. 增加可用时间批量更新的 store action

问题：

- 如果批量选择几十个时间格后逐个调用单格更新，会导致已有排班结果被重复重算。

处理：

- 在 Zustand store 中新增 `setAvailabilityBatch(employeeId, slotIds, status)`。
- 批量更新同一员工多个时间格的可用状态。
- 当批量设置为 `busy` 时，沿用原有逻辑：移除该员工在对应时间格中的已有排班。
- 如果已有排班结果，只在批量更新后统一重新计算一次缺人、工时和统计结果。

涉及文件：

- `src/features/project/useProjectStore.ts`

### 7. 清理员工详情中的静态示例标签

问题：

- 员工详情面板下方显示“偏好 10:00 后排班”和“忙碌是课程时间……”两个标签。
- 其中“偏好 10:00 后排班”只是静态示例文案，并没有对应员工字段，也不会影响算法。
- 该文案容易让用户误以为当前员工存在一个真实的 10:00 后排班偏好设置。

处理：

- 移除员工详情面板下方的两个静态标签。
- 保留姓名、目标工时和基础说明。
- 当前实际影响算法的偏好来源仍是时间表中的 `不偏好` 状态；被标记为 `不偏好` 的时间格可以排班，但会降低候选评分。

涉及文件：

- `src/app/App.tsx`
