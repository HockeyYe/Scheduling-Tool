# 可用时间批量编辑需求文档

## 1. 背景

当前“员工与可用时间”页面支持按员工录入一周可用时间。用户需要先在左侧选择员工，再在中间时间表中逐个点击单元格，将时间段标记为“可排”“忙碌”或“不偏好”。

当员工有连续课程、整段不可用时间或多天重复空闲时，逐格点击成本较高，且容易漏选。第一期需要增强当前单员工时间表的交互能力，让排班负责人可以通过拖拽选择多个时间格，再一次性批量修改状态。

## 2. 目标

- 降低录入单个员工可用时间的点击次数。
- 让当前可用时间表具备明确的 hover、选中和批量应用反馈。
- 支持状态按钮“可选中 / 可取消选中”的新交互，避免拖拽选区完成后误触批量改状态。
- 在不改变现有数据结构和排班算法的前提下，复用现有 `AvailabilityMap` 与可用时间更新逻辑。
- 第一版聚焦桌面端鼠标操作，不处理手机端触控交互。

## 3. 范围

### 3.1 本期必做

- 在当前“单个员工的一周可用时间表”中支持单元格 hover 效果。
- 支持鼠标拖拽形成矩形选区。
- 支持选中多个单元格后，通过顶部状态按钮批量应用状态。
- 支持顶部状态按钮取消选中，即三个状态可以全部处于未选中状态。
- 拖拽选择完成并松开鼠标后，顶部状态自动变为未选中状态。
- 支持清晰展示当前已选中的单元格，并在批量应用后继续保留选区。
- 只有用户点击其他单元格或表格外区域时，才取消当前选区。
- 批量设置为“忙碌”时，沿用当前逻辑：自动移除该员工在对应时间段的已有排班，并重新计算缺人和员工统计。

### 3.2 本期不做

- 不改成“员工 × 时间”的多员工总览表。
- 不支持跨员工批量编辑。
- 不支持手机端长按、多指或触屏拖拽。
- 不支持任意形状画笔式选择。
- 不支持 Excel 式 Ctrl/Shift 追加选择，作为后续版本规划。
- 不新增可用状态类型。
- 不修改排班算法核心逻辑。

## 4. 用户角色

主要用户是咖啡店排班负责人。用户通常拿到某个员工的课程表或空闲时间后，需要快速把一段连续时间标记为忙碌、不偏好或可排。

## 5. 页面位置

功能位于：

- 页面：员工与可用时间
- 区域：中间“可用时间录入”面板
- 表格：当前选中员工的周一至周五、08:00-16:30、30 分钟粒度时间表

当前员工仍由左侧员工列表决定。批量编辑只作用于当前员工。

## 6. 交互设计

### 6.1 顶部状态按钮

顶部状态按钮包含：

- 可排
- 忙碌
- 不偏好

新的状态按钮规则：

- 三个状态不再必须始终选中一个。
- 用户在未选中表格里任意区域时，状态栏按钮均为不可选中状态。
- 用户点击未选中的状态按钮且当前已有单元格和区域被选中时，该按钮变为选中状态，其他状态按钮取消选中。
- 用户重复点击当前已选中的状态按钮时，该按钮取消选中，三个状态进入全部未选中状态。
- 当三个状态均未选中时，点击单元格或选区不应修改可用时间状态。
- 当按钮被选中时，将会改变当前所选的单元格或者区域的状态值，且状态按钮变为未选中状态。
- 状态按钮的选中态只表示“下一次应用的目标状态”，不代表当前表格选区本身的状态。

### 6.2 Hover 效果

当鼠标悬停在可用时间单元格上时：

- 单元格边框或背景应有轻微高亮。
- 鼠标指针显示为可点击或可选择状态。
- 如果当前未选择员工，单元格保持禁用状态，不触发 hover 强反馈。

Hover 效果的目的不是改变数据，只提示该格可以被选中或编辑。

### 6.3 单击行为

单击行为按是否存在选区区分。

无选区时：

- 如果顶部已选中某个状态，单击单元格会立即将该单元格改为所选状态。
- 如果顶部三个状态均未选中，单击单元格只作为普通点击，不修改该单元格状态。

已有选区时：

- 点击任意其他单元格，取消原选区以及按钮选中状态。

### 6.4 拖拽选择行为

用户可以在时间表中按住鼠标左键，从一个单元格拖拽到另一个单元格，形成矩形选区。

矩形选区规则：

- 起点为鼠标按下的单元格。
- 终点为鼠标当前悬停或松开的单元格。
- 选区包含起点和终点之间的所有日期列与时间行交叉单元格。
- 选区只在当前员工的时间表内生效。
- 拖拽过程中，矩形范围内单元格应实时显示选中状态。
- 鼠标松开后，选区保持选中。
- 鼠标松开后，顶部三个状态按钮自动进入未选中状态。
- 用户必须再次手动选择“可排 / 忙碌 / 不偏好”中的一个状态，才能对选区执行批量修改。

示例：

- 从“周一 09:00”拖到“周三 11:00”，应选中周一至周三、09:00 至 11:00 范围内所有 30 分钟格。
- 从右下向左上反向拖拽，也应得到同样的矩形选区。

### 6.5 批量应用状态

用户完成选区后，顶部状态处于未选中状态。此时用户需要点击一个状态按钮，系统才将选区全部修改为该状态。

批量应用规则：

- 如果存在选区，且用户点击某个未选中的状态按钮，系统将选区内所有单元格设置为该状态。
- 批量应用完成后，选区继续保留。
- 批量应用完成后，被点击的状态按钮保持选中，方便用户看到刚刚应用的目标状态。
- 如果用户再次点击该状态按钮，按钮取消选中，但不撤销刚才已经应用的数据修改。
- 如果存在选区但顶部三个状态均未选中，系统不应修改任何单元格。

保留选区的目的：

- 让用户可以明确看到刚才修改的是哪些格子。
- 允许用户发现选错状态后，在选区仍然保留的情况下再次点击另一个状态进行覆盖修改。
- 避免批量应用后选区立刻消失，导致用户无法确认操作范围。

### 6.6 选区反馈

选中单元格需要与普通状态色区分开。

建议视觉层级：

- 单元格原有状态 badge 继续展示。
- 选中单元格增加明显但不过度的外框、内阴影或淡色覆盖层。
- 拖拽起点和当前终点可以不做特殊区分，MVP 只需要选中范围清晰。

### 6.7 清空选区

选区不因批量应用状态而自动清空。

用户可以通过以下方式清空选区：

- 点击其他单元格。
- 点击表格外区域。
- 切换员工。
- 切换到其他页面。

## 7. 数据与状态逻辑

### 7.1 数据模型

不新增领域数据模型。仍使用现有结构：

```ts
type AvailabilityMap = Record<string, Record<string, AvailabilityStatus>>;
```

批量选择属于临时 UI 状态，不需要持久化到 localStorage，也不需要导入导出。

### 7.2 前端临时状态

建议在 `AvailabilityPage` 或拆分后的 `AvailabilityGrid` 中维护：

- `activeStatus`：当前顶部选中的目标状态，类型建议为 `AvailabilityStatus | undefined`。
- `selectionAnchor`：拖拽起点单元格。
- `selectionFocus`：拖拽当前终点单元格。
- `selectedSlotIds`：根据起点和终点计算出的矩形选区 slotId 集合。
- `isDraggingSelection`：是否正在拖拽选择。

单元格定位建议使用：

- day index：周一至周五列索引。
- time index：当前时间行索引。
- slotId：最终写入 availability 时使用。

### 7.3 批量更新

现有 store 只有单格 `setAvailability(employeeId, slotId, status)`。开发时有两种实现路径：

- MVP 可先循环调用 `setAvailability`，实现成本低。
- 更推荐新增 `setAvailabilityBatch(employeeId, slotIds, status)`，一次性更新 availability 和 scheduleResult，避免多次重复重算。

推荐实现 `setAvailabilityBatch`，原因：

- 批量编辑时可能一次修改几十个格。
- 当前 `setAvailability` 每次都会在已有排班结果存在时重新计算，循环调用会导致重复计算。
- 批量 action 更容易测试，也更符合功能语义。

### 7.4 与已有排班结果联动

沿用现有逻辑：

- 当状态改为 `busy` 时，如果该员工在对应 slot 已有排班，应自动移除这些 assignment。
- 移除后调用现有 `recalculateScheduleResult`，重新计算缺人、员工工时、偏好冲突等结果。
- 当状态改为 `available` 或 `dispreferred` 时，不自动新增排班，只更新可用状态并重新计算已有结果的统计。

## 8. 边界情况

- 未选择员工时，时间格不可编辑，不允许拖拽选择。
- 顶部三个状态均未选中时，单击单元格不修改状态。
- 拖拽完成后，顶部状态必须自动取消选中。
- 拖拽从单元格开始但在表格外松开，应以最后进入过的单元格作为终点；如果没有有效终点，则只选起点。
- 拖拽过程中不应选中页面文本。
- 快速点击单元格不应被错误识别为大范围拖拽。
- 切换员工后，旧员工的选区必须清空，避免误操作到新员工。
- 如果选区中的某些单元格已经是目标状态，批量应用时可以重复写入，不需要特殊提示。
- 如果已有排班结果，批量改为忙碌后可能产生新的缺人时段，应在现有缺人提示中体现。

## 9. 建议开发拆分

### 9.1 Store 层

新增批量 action：

```ts
setAvailabilityBatch: (
  employeeId: string,
  slotIds: string[],
  status: AvailabilityStatus,
) => void;
```

行为：

- 批量更新 `availability[employeeId][slotId]`。
- 如果 `status === "busy"` 且存在 `scheduleResult`，移除该员工在这些 slot 中的 assignments。
- 如果存在 `scheduleResult`，统一调用一次 `recalculateScheduleResult(get())`。

### 9.2 UI 层

建议将当前 `AvailabilityRow` 逐步收敛成更容易处理矩形选择的网格组件：

- 父组件统一掌握所有 slot 的行列信息。
- 单元格接收 `isSelected`、`isDragging`、`status`、`slot` 等 props。
- 鼠标事件集中处理：
  - `onMouseDown`
  - `onMouseEnter`
  - `onMouseUp`
- 顶部状态按钮支持 `activeStatus?: AvailabilityStatus`，并允许重复点击取消选中。
- 拖拽结束时调用 `setActiveStatus(undefined)`，让状态按钮进入未选中状态。
- 批量应用后不清空 `selectedSlotIds`。

### 9.3 样式层

新增或调整样式：

- `.cell:hover`
- `.cell.selected`
- `.cell.dragging`
- `.availability-selection-summary`
- `.tab-button.active`
- `.tab-button` 的未选中状态需要足够清楚，避免用户误以为已有状态会被应用。

样式需保持与当前面板风格一致，不引入新的大面积视觉主题。

### 9.4 测试

建议增加 store 测试：

- 批量设置多个 slot 为 busy 后，availability 全部更新。
- 批量设置为 busy 后，对应员工在这些 slot 的 assignments 被移除。
- 批量设置只触发一次结果重算的实现可通过结构设计保证，不强制写调用次数测试。

建议增加组件交互测试或手动验收：

- 重复点击状态按钮可以取消选中。
- 拖拽完成后状态按钮自动未选中。
- 拖拽完成后点击状态按钮会批量应用到选区。
- 批量应用后选区仍保留。
- 点击其他单元格或表格外区域后选区清空。

## 10. 验收标准

### 10.1 基础交互

- 鼠标悬停在可编辑时间格上，有清晰 hover 效果。
- 状态按钮可以选中，也可以通过重复点击取消选中。
- 顶部三个状态可以全部处于未选中状态。
- 无选区且有状态选中时，单击时间格可按当前状态修改单格。
- 无选区且没有状态选中时，单击时间格不会修改状态。
- 从任意一个时间格拖到另一个时间格，可以形成矩形选区。
- 反向拖拽也能形成正确矩形选区。
- 拖拽松开后，顶部状态自动变为未选中。
- 选区内所有格子有统一、清晰的选中视觉反馈。

### 10.2 批量修改

- 选中多个格子并松开鼠标后，不会立即修改这些格子的状态。
- 选中多个格子后点击“忙碌”，所有选中格子变为忙碌。
- 选中多个格子后点击“可排”，所有选中格子变为可排。
- 选中多个格子后点击“不偏好”，所有选中格子变为不偏好。
- 批量应用完成后选区继续保留。
- 批量应用完成后再次点击另一个状态，可以覆盖修改同一选区。
- 点击其他单元格或表格外区域后，选区取消。

### 10.3 排班联动

- 如果某员工已被安排在某些时间格，批量改为忙碌后，该员工会从这些时间格的排班结果中移除。
- 移除后缺人统计、员工工时统计会更新。
- 批量改为可排或不偏好不会自动新增排班。

### 10.4 状态切换

- 切换员工后，旧选区清空。
- 切换员工后，顶部状态建议进入未选中状态，避免误操作。
- 未选择员工时，不能拖拽选择或修改可用状态。
- 刷新页面后不会保留选区，但会保留已批量修改后的可用时间数据。

## 11. 后续版本规划

后续可以逐步增强到类似 Excel 的选择体验：

- 支持 Ctrl 或 Cmd 逐个追加/取消选中单元格。
- 支持 Shift 从上次选中点扩展矩形范围。
- 支持拖拽后不自动清空选区，允许连续批量操作。
- 支持键盘方向键移动焦点。
- 支持复制某一天的可用时间到其他日期。
- 支持跨员工复制当前员工的一段可用时间模板。

这些能力不进入本期 MVP，避免第一期交互复杂度过高。
